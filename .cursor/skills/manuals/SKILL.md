# マニュアル作成スキル

操作マニュアルは **「誰が・どこで・何をするか」** だけを書く。内部実装・未使用 API・今後の予定は開発ドキュメントへ回す。

先に [documentation スキル](../documentation/SKILL.md) の共通ルール（日本語、実装準拠、記号、配置）に従う。

## 対象ファイル

| マニュアル | パス | 対象ロール |
|------------|------|------------|
| 目次 | `docs/manuals/README.md` | 全員 |
| 学習者 | `docs/manuals/learner.md` | `learner` |
| 講師 | `docs/manuals/instructor.md` | `instructor` |
| 管理者 | `docs/manuals/admin.md` | `org_admin` / `content_admin` |
| 開発者 | `docs/manuals/developer.md` | 開発メンバー |
| 運用者 | `docs/manuals/operator.md` | 起動・監視・障害対応 |

開発者マニュアルは「ローカルで動かす・テストする」まで。設計の詳細は `docs/architecture.md` などへリンクする。

ブラウザで読むときは **マニュアルアプリ**（`manuals/web`、開発時 http://localhost:5210）を使う。本文の正本は上表の Markdown であり、アプリに手順を複製しない。`cd manuals/web && npm run dev` で他サービスなしに起動できる。

## 構成（必須セクション）

各ロール別マニュアルは次の順にする。

1. このマニュアルでできること
2. 使うアプリと URL（開発時のポートを明記）
3. ログイン
4. 日常業務の手順（番号付き。1 手順 = 1 結果）
5. 画面項目の説明（必要なときだけ表）
6. できないこと・注意
7. 困ったとき（`docs/troubleshooting.md` へリンク可）

## 手順の書き方

```markdown
### 教材を開く

1. 本棚でカードをクリックします。
2. PDF ビューアが開き、前回のページに戻ります。

結果: ツールバーに教材タイトルとページ番号が表示されます。
```

- ボタン名は画面どおり（「本棚へ戻る」など）
- キーボードは `←` `→` のように記号で書く
- 開発用アカウントは `demo` / `demo` のようにコードと一致させる
- モバイルとデスクトップで操作が違う場合は分けて書く

## 書いてはいけないこと

- 学習者マニュアルに管理 API の curl 例
- 「将来こうなります」を手順の中に混ぜる
- 未実装（完全オフライン閲覧など）を普通の手順として書く
- ロールが使えない画面への誘導（学習者を管理画面へ送らない）

## 更新タイミング

| 変化 | 直すマニュアル |
|------|----------------|
| 本棚・ビューア・注釈の UI | `learner.md`（講師向けに差分があれば `instructor.md`） |
| アカウント・ライセンス・教材管理 | `admin.md` |
| 起動スクリプト・ポート・テストコマンド | `developer.md` `operator.md` |
| マニュアルアプリの画面・ルート | `docs/manuals/README.md` と各ロールの URL 表 |
| LMS のコース・起動 | `instructor.md` |
| ログイン URL・SSO の流れ | 全マニュアルの「ログイン」節 |
