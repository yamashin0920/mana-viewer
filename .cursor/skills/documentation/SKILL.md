# ドキュメント作成スキル

リポジトリのドキュメントは **日本語・実装準拠・単一の情報源** で書く。推測で「実装済み」と書かない。未実装は未実装と明示する。

このスキルを読んだら、対象ドキュメントの種類に応じて `docs/README.md` の配置ルールに従う。操作マニュアルは追加で [manuals スキル](../manuals/SKILL.md) を読む。

## いつ使うか

- 新規機能・API・画面を実装したあと
- `docs/`・各パッケージ README・`.cursor/rules` を書く・直すとき
- 要件と実装の差分を文書化するとき
- エージェントが「ドキュメントを全部書く」依頼を受けたとき

## 情報源の優先順位

1. **コード**（`viewer/` `admin/` `auth/` `mock-api/`）
2. **既存の要件マトリクス**（`docs/requirements.md`）
3. **パッケージ README**（起動手順の要約）
4. それ以外は「想定」「未実装」と書く。想像で完成扱いにしない

## 置き場所

| 種類 | パス | 読者 |
|------|------|------|
| 目次 | `docs/README.md` | 全員 |
| 要件・実装状況 | `docs/requirements.md` | 開発・PdM |
| アーキテクチャ | `docs/architecture.md` | 開発 |
| ドメインモデル | `docs/domain-model.md` | 開発 |
| 用語集 | `docs/glossary.md` | 全員 |
| 開発手順 | `docs/development/` | 開発 |
| API 仕様 | `docs/api/` | 開発 |
| 機能仕様 | `docs/features/` | 開発 |
| セキュリティ | `docs/security.md` | 開発・運用 |
| 運用 | `docs/operations.md` | 運用 |
| トラブルシュート | `docs/troubleshooting.md` | 開発・運用 |
| 操作マニュアル | `docs/manuals/` | 利用者（ロール別） |
| パッケージ起動メモ | 各ディレクトリの `README.md` | 開発（短く保つ） |

ルート `README.md` は入口だけ。詳細は `docs/` へリンクする。同じ手順を 3 箇所に全文コピーしない。

## 文書の共通ヘッダ

各 `docs/**/*.md` の先頭は次の順にする。

```markdown
# 文書タイトル

> 読者: （誰向けか）
> 最終更新: YYYY-MM-DD
> 関連: [リンク](相対パス)

冒頭 2〜4 行で「この文書は何を決めるか」を書く。
```

- 日付は実装を確認した日
- 関連リンクは 2〜6 本。循環リンクしすぎない
- 英語ファイル名、日本語本文

## 文体

- です・ます調（マニュアル）／である調は使わない
- 箇条書きと表を優先。長い散文は避ける
- UI 文言は画面の表記と一致させる（例: 「本棚」「注釈」「ライセンス」）
- コード・パス・コマンドはバッククォート
- ポート番号・環境変数・ロール名はコード上の値を使う

## 実装状況の記号

`docs/requirements.md` と同じ記号だけを使う。

| 記号 | 意味 |
|------|------|
| ✅ | UI + API 連携まで実装済み |
| 🔶 | 部分実装（API のみ、スキーマのみ、デモモード） |
| ❌ | 未実装 |
| ➖ | スコープ外 |

機能仕様では各節の先頭に状態を書く。マニュアルでは **使える機能だけ** を手順にし、未実装は「現在使えない機能」にまとめる。

## 機能・API を足したときの更新セット

コードを変えたら、該当するものを同じ変更で直す。

1. `docs/requirements.md` の該当行
2. 対応する `docs/features/*.md`
3. API なら `docs/api/*.md`
4. 画面操作が変わるなら `docs/manuals/*.md`
5. 起動・ポート・環境変数なら `docs/development/getting-started.md` とルート README
6. 新しい概念なら `docs/glossary.md` と `docs/domain-model.md`

## 書いてはいけないこと

- 存在しない画面・エンドポイントを完成扱いで書く
- 本番インフラ（Kubernetes 等）を、リポジトリに無いのに導入済みと書く
- 機密（本番シークレット、利用者の実パスワード以外の開発用 demo アカウントは書いてよい）
- 日付のない「現状」表現。必ず最終更新日を置く
- パッケージ README を百科事典化すること。詳細は `docs/` へ

## テンプレート（機能仕様）

```markdown
# 機能名

> 読者: 開発者
> 最終更新: YYYY-MM-DD
> 関連: [要件](../requirements.md) / [API](../api/platform.md)

## 目的
## 対象ユーザー（ロール）
## 状態
## 画面とルート
## 主な操作
## データと API
## 権限
## テスト
## 未実装・制約
```

## テンプレート（API）

```markdown
# API 名

> 読者: 開発者
> 最終更新: YYYY-MM-DD

## ベース URL と認証
## エンドポイント一覧
## リクエスト / レスポンス
## エラー
## 開発用データ
```

エンドポイント表の列は **メソッド / パス / 認証 / 権限 / 説明** で揃える。

## 完了条件

- `docs/README.md` からすべての文書に辿れる
- 実装と矛盾する記述が無い
- 未実装が ✅ になっていない
- マニュアルはロール別に「開く場所 → 操作 → 結果」がある
